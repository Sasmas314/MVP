# Обзор VLM-моделей, пригодных для задачи

Vision-Language Models (VLM) в контексте **Key Information Extraction (KIE)** можно использовать двумя основными способами:

1. **Документ-понимание (end-to-end)**  
   Модель сразу получает изображение/документ и генерирует структурированный JSON  
   (аналог подхода Donut, но в instruction-формате).

2. **Пост-обработка OCR**  
   Модель работает поверх извлеченного текста:
   - нормализует данные  
   - связывает поля  
   - исправляет ошибки OCR

| **Qwen-VL** | локально (веса) | да | зависит от размера; желательно GPU | высокая | Хорошо работает с текстом и привязкой к изображению |
| **Qwen2-VL** | локально (веса) | да | улучшена работа с разными разрешениями | высокая | Более стабильна на документах |
| **Qwen2.5-VL** | локально (веса) | да | оптимизированный инференс | высокая | Сильна в document parsing и OCR |

# Практический вывод

Для задачи автоматического извлечения данных из документов (билеты, чеки, бронирования):

- оптимальный выбор для **локального MVP** — семейство **Qwen**
- в частности, **Qwen3-VL-8B**:
  - поддерживает мультиязычность  
  - хорошо работает с длинными документами  
  - умеет извлекать структурированные данные  

## Рекомендуемая архитектура

Лучший практический вариант — **гибридный подход**:

### 1. Основной путь (VLM)
- отправка документа напрямую в модель  
- получение JSON  

### 2. Фолбэк (OCR)
Использовать при:
- плохом качестве скана  
- мелком тексте  
- нестабильном ответе модели  

Подходящие инструменты:
- PaddleOCR  
- Tesseract  
- TrOCR
